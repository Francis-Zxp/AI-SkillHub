# AI SkillHub v3.0.7 Competitive Audit

Reviewed on 2026-07-26 from current public upstream documentation.

| Project | Current public strength | AI SkillHub comparison |
|---|---|---|
| jtianling/skills-manager | 44 tools, registry, dependencies, groups, project/global deployment | AI SkillHub has a richer visual/explainability layer but materially narrower adapter coverage |
| runkids/skillshare | 60+ tools, multi-Git hosting, team config, security audit, single binary, offline UI | AI SkillHub has stronger source/parent/child visualization and personal quality evidence; team/declarative workflows lag |
| Auran0s/Sklm | 30 agents, global store, project scopes, registry discovery, per-agent variants | AI SkillHub needs explicit Agent variants and broader project deployment |
| Agent Desk | Rich editor/file tree, collections, marketplace, MCP, full-text search, three platforms | AI SkillHub is stronger in relationship atlas, source governance and recoverability; editing/search/platform breadth lag |
| GitHub Copilot skills | Official project/personal paths, reload/info/remove commands, explicit script trust warning | AI SkillHub's staged per-file scan and review gate are aligned; it must never auto-trust script permissions |

## Current position

v3.0.7 is a credible Windows local-first beta and a differentiated portfolio
product. It can compete on:

- a real-data capability atlas rather than a decorative dashboard;
- source-scoped parent/child routing and explicit same-name boundaries;
- private parent/child ratings separated from GitHub popularity;
- explainable evidence-aware quality signals;
- bounded import staging and security review;
- source pin/diff/verified rollback;
- stable user data, recoverable migration and signed in-app updates;
- Adapter Doctor evidence instead of creating fake tool directories.

It is not yet ecosystem-leading in:

- macOS/Linux delivery;
- adapter count;
- rich editing, file tree, full-text search and MCP management;
- registry/community discovery and team manifests;
- Agent-specific variants and declarative cross-machine setup;
- optional functional evaluation of Skill quality;
- 1000+ node performance budgets and a complete static accessibility view;
- code splitting and community support infrastructure.

## Next rational priorities

1. Page-level code splitting and a repeatable 650/1000/1500-node frame budget.
2. Static/list accessibility equivalent for every graph action.
3. Agent variants plus export/import of a declarative, privacy-safe library
   manifest.
4. Full-text Skill/source search and a safe read-only file tree before a rich
   editor.
5. Optional sandboxed functional evaluation only after a separate security and
   privacy design review.
6. Cross-platform packaging only when adapter paths, updater signing and
   recipient simulations have equivalent gates.
