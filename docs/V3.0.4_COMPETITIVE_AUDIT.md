# AI SkillHub v3.0.4 — Reference and Competitor Audit

Reviewed on 2026-07-24. The removed `其它人的优秀项目案例` folder was not
used as a dependency; current public projects and first-party documentation
were reviewed instead.

## Experience references

### FIELD — data-authentic spatial systems

- [IBM Under the Surface](https://field.io/work/ibm-under-the-surface)
- [Seeing in Gamma](https://field.io/work/applied-intuition-seeing-in-gamma)
- [IBM × Grammy Museum Music Discovery](https://field.io/work/ibm-x-grammy-museum-music-discovery-interface)

Transferable lesson: motion, colour and distance should expose a real model.
AI SkillHub therefore maps source popularity, category, parent/child structure,
ratings and use events to distinct visual signals. It does not copy FIELD's
assets, footage or layouts.

### Linear — calm application hierarchy

- [Linear UI Refresh](https://linear.app/changelog/2026-03-12-ui-refresh)

Transferable lesson: navigation, page headers, view controls and icon optical
size must be consistent. The dramatic home scene should not make editing and
diagnostic pages visually noisy.

### Figma, Sigma and Pixi — infinite-canvas performance

- [Figma rendering powered by WebGPU](https://www.figma.com/blog/figma-rendering-powered-by-webgpu/)
- [Sigma.js](https://www.sigmajs.org/)
- [PixiJS ParticleContainer](https://pixijs.com/8.x/guides/components/scene-objects/particle-container)

Transferable lesson: use level of detail, render only meaningful
neighbourhoods, adapt quality to frame time and preserve a compatibility path.
v3.0.4 keeps Canvas 2D for low-risk desktop compatibility, removes expensive
per-frame gradients, and adds explicit LOD/performance telemetry. A WebGL
renderer remains an optional future step, not an untested release dependency.

## Skill-management references

### GitHub CLI `gh skill`

- [Preview a Skill without installing](https://cli.github.com/manual/gh_skill_preview)
- [Install, pin, update and publish Skills](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills)

Useful patterns:

- preview every file before installation;
- preserve provenance (repository, ref and tree SHA);
- allow pinning;
- dry-run validation before publishing.

AI SkillHub v3.0.4 applies the same product principles to staged source
inspection, origin metadata, commit pinning, update-diff summaries and
verified-backup rollback. It does not shell out to `gh skill` or require
GitHub CLI on recipient computers.

### ASM and skills-manage

- [ASM](https://github.com/luongnv89/asm)
- [skills-manage](https://github.com/iamzhihuix/skills-manage)

Useful patterns:

- multi-agent adapters are a registry, not scattered conditions;
- duplicate audit should explain why candidates collide;
- detection should show evidence and a repair route;
- one canonical Skill copy can be linked to many agents.

AI SkillHub keeps its stronger parent-router and exact-name conflict model, but
uses these projects as a baseline for adapter breadth and diagnostic clarity.

### iFlytek SkillHub

- [iflytek/skillhub](https://github.com/iflytek/skillhub)

Useful patterns:

- security scanning cannot be bypassed by a privileged publish path;
- versions and channels are first-class;
- audit evidence belongs to governance, not to beginner settings.

AI SkillHub remains local-first and lightweight rather than adopting the
enterprise server architecture.

### Content hash and update provenance

- [Elastic Agent Skills](https://github.com/elastic/agent-skills)

Useful pattern: track source and content hash so update checks can distinguish
an upstream change from a user-modified local copy.

## v3.0.4 decisions

- Keep the public release free of every user's private sources and ratings.
- Use a deterministic offline metadata analyzer; never execute imported code to
  describe it.
- Add per-file content-risk evidence before source promotion.
- Preserve manual metadata over inferred metadata.
- Recover legacy data by copying and verifying one source at a time; never
  overwrite a newer destination.
- Keep advanced audit, release and migration reports behind progressive
  disclosure.
- Pin/diff/rollback only for sources with usable Git history. A rollback needs
  a verified backup and preserves the current full tree before replacement.
- Treat GitHub stars as popularity only. The optional local quality score uses
  four explainable evidence types: personal/child rating (40%), indexed health
  (25%), recorded local use (15%), and security scanning (20%). Missing
  evidence is excluded and fewer than two types produce no headline score.
- Enable old-version cleanup only after a successful v4 manifest and SQLite
  health gate. Cleanup is allowlist-only, confirmation-based, recoverable, and
  excludes the developer `release` directory.

## Annotation 1 gap closure

1. **Per-file import security — completed with a boundary.** Staging and
   promotion produce bounded, redacted file-level findings. High risk blocks
   promotion and medium risk stays isolated. Static scanning is evidence, not
   a proof that arbitrary code is safe.
2. **Pin, diff and rollback — completed for Git-backed sources.** The app stores
   a commit pin, previews upstream revision and line/file deltas, preserves
   cached status honestly when offline, and rolls back only from a verified
   backup after snapshotting the current tree.
3. **Quality beyond stars — completed as a local evidence score.** Rating,
   health, actual recorded use and security are combined only when at least two
   independent types exist. Stars remain an uncombined popularity measure;
   metadata completeness is not quality.
4. **Adapter Doctor — completed.** Desktop presence, Code capability, PATH
   freshness, Skills-directory readiness and stale residue are separate
   diagnoses with redacted evidence and a safe next action.
5. **1000+ node rendering — completed as guarded Canvas 2D LOD.** The renderer
   crosses detail bands at 650 and 1200 nodes, reduces work during interaction,
   pauses in the background, respects reduced motion and retains a static
   compatibility view. WebGL/WebGPU remains an optional future experiment, so
   v3.0.4 does not claim an unmeasured universal frame rate.
6. **Old-version cleanup — completed with explicit consent.** Only three
   allowlisted legacy locations can appear after migration and database health
   pass. Selected data is moved to a recoverable backup. `release` remains a
   developer-managed folder.
7. **Competitor lessons — adopted selectively.** ASM informed doctor/audit/
   security evidence, skills-manage reinforced the local-first multi-adapter
   desktop model, and iFlytek informed version/audit separation. Team registry,
   RBAC and a mandatory server remain outside the local 3.x scope.
