# AI SkillHub v3.2.3

## 中文说明

v3.2.3 是 v3.2.2 的正式补丁版，修复两个在别人电脑上更容易出现的问题，界面布局、操作流程和安全边界保持不变。

- **没有安装 Git 的电脑现在也能更新 Skill 来源。** 本机没有可用 Git 时，软件会改用内置的 GitHub ZIP 下载器安装来源；这种副本不含 `.git`，因此 `git pull` 永远读不到它，来源会一直停留在安装当天的内容，同步报告也只会提示“不支持自动更新”。现在点击“同步并刷新”会重新下载这些来源的 GitHub 快照，同步报告也会给出每个来源的真实结果。
- **浅色主题不再出现大片灰色阴影。** 所有浅色主题此前都用“半透明深色”绘制能力星图的光晕，结果在浅色背景上呈现为一大团灰色污渍，压在首页标题后面并让整个窗口发灰。浅色主题的光晕、轨道环、球壳与尘埃透明度已大幅降低，活体图谱浅色主题的首页渐变也同步调淡。深色主题不受影响。

### 安全边界

快照刷新只会处理软件自己管理的来源目录、且带有软件自己写入的 `.skillhub-source.json` 的副本；真正的 Git 克隆和已固定版本的来源都不会被碰。新副本会先通过安全扫描；内容与本地一致时会直接跳过、不重写任何文件；替换前会把现有副本移入保留的备份目录，写入失败会自动还原。

## English

v3.2.3 is the formal patch release for v3.2.2. It fixes two problems that show up most often on someone else's computer, and preserves the existing layout, workflows, and safety boundary.

- **Machines without Git can now update their Skill sources.** When no usable Git is present, the app installs sources with its built-in GitHub ZIP downloader. Those copies carry no `.git`, so `git pull` could never reach them: the source stayed frozen at its install-time content and the sync report only said automatic updates were unavailable. "Sync / refresh" now re-downloads the GitHub snapshot for those sources, and the sync report names the real result for each one.
- **Light themes no longer show a large grey shadow.** Every light theme drew the capability atlas atmosphere as a wide, translucent dark tint, which read as a grey smudge behind the homepage headline and washed out the whole window. The light-theme aura, rings, shell, and dust now use a much lower alpha, and the Living Atlas light hero gradient was softened to match. Dark themes are unchanged.

### Safety boundary

A snapshot refresh only ever touches folders inside the app-managed sources root that carry the app's own `.skillhub-source.json`; real Git clones and pinned sources are never touched. The new copy is security-scanned first, an unchanged snapshot is skipped without rewriting anything, and the existing copy is moved to a retained backup before the swap and restored automatically if the swap fails.

## Release boundary

The fallback updater manifest is published only after signed assets are uploaded, anonymously downloaded, hash-compared, and verified with the embedded updater key.
