# AI SkillHub v3.1.5

v3.1.5 repairs the core Skill delivery path for ChatGPT Desktop and Codex.

## Fixed

- Publishes enabled Skills to the current OpenAI user directory,
  `$HOME/.agents/skills`, and verifies every delivered `SKILL.md`.
- Detects ChatGPT/Codex desktop-only installations as valid recipients. Codex
  CLI is no longer a false prerequisite for desktop Skill discovery.
- Keeps an existing `$HOME/.codex/skills` directory synchronized for old Codex
  builds, but never creates that legacy directory on a clean computer.
- Uses real home paths for disk checks instead of privacy-redacted `~` strings,
  eliminating false “Codex missing” badges.
- Fixes Windows PowerShell 5.1 multi-item JSON parsing and refuses to alter a
  recipient when a non-empty policy has zero valid matches.
- Maps SQLite Skills to their final Host-visible names, including conflict
  aliases and generated parent routers, before publishing or showing status.
- Makes Skill and Source enable switches control the actual delivery allowlist.
  Disabled entries and invalid manifests are not published.
- Loads cached data immediately, then refreshes tool detection, repairs missing
  links, and checks the recipient again in the background.
- Corrects invocation guidance: use `@` in ChatGPT Desktop; use `/skills` or
  `$skill-name` in Codex. Restart the host if a newly published Skill is not
  visible yet.

## Clearer library

- Intelligent recognition now writes one or two compact sentences describing
  the capability and, for a parent source, its main child Skills.
- Removed the duplicated “Usage” paragraph from Skill cards.
- Hid the old display-only Task bundles page. It did not create, edit, or
  publish a real bundle and will return only after those operations are real
  and verifiable.

## Safety and data

AI SkillHub only removes managed links that point back into its own active Skill
view. A real same-name user folder is moved to a recoverable backup before a
managed link is created. Sources, folders, ratings, tags, settings, and SQLite
state remain in the independent user-data directory during upgrade.

- Rust: 127 passed, 0 failed, 5 explicitly network-gated.
