# AI SkillHub v3.0.1 — Recipient Compatibility Fix

v3.0.1 focuses on the failures found on a second Windows computer after the
v3.0.0 release. It keeps the Living Atlas interface and fixes installation,
source import, AI-tool detection, and production Settings.

## What is fixed

- GitHub imports work even when Git is not installed or is not available in
  `PATH`. AI SkillHub automatically falls back to a secure GitHub archive/API
  download with path, file-count, and size limits.
- Prompt/reference repositories without `SKILL.md` are classified correctly and
  are never installed as Skills.
- Refreshing AI tools no longer fails with a SQLite foreign-key error when
  preset/workspace policies already exist.
- Claude Desktop installed through the current Windows MSIX package is detected,
  even before a `claude` CLI command or `%USERPROFILE%\.claude` folder exists.
- Claude Code native and legacy installations, plus custom
  `CLAUDE_CONFIG_DIR`, are recognized.
- Claude’s local path is described accurately: it serves Claude Code and the
  Desktop Code tab. Chat/Cowork custom Skills remain managed inside Claude.
- Ordinary Settings no longer exposes build/release instructions, internal QA
  controls, dry-run executors, or rollback implementation details.
- Release packaging always takes the executable from the current Tauri release
  build.

## Privacy and safety

- A new support report contains version, Git availability, proxy-presence,
  SQLite foreign-key health, and the latest source-import summary.
- It does not include tokens, proxy addresses, Skill contents, the SQLite
  database, or absolute user paths.
- GitHub fallback downloads accept only bounded HTTPS GitHub content, reject
  path traversal and symbolic links, and install only folders containing
  `SKILL.md`.

## Install

1. Download `AI-SkillHub-3.0.1.zip` from this Release.
2. Extract the whole ZIP to a writable folder.
3. Run `AI SkillHub.exe`.
4. On the AI Tools page, click “Detect Local Tools” after installing or updating
   Claude Desktop/Claude Code.

If a problem remains, open **Safety & Support**, generate the support report,
and share `latest-diagnostics-export.json`.
