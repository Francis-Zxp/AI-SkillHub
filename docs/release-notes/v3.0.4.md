# AI SkillHub v3.0.4 — Spectral Gravity and Explainable Imports

v3.0.4 makes the library easier to understand, safer to import, and more
resilient when upgrading from an older portable copy.

中文摘要：本版重做真实能力星图，加入离线资料识别、逐文件安全复核、旧资料
可恢复迁移、来源版本锁定/差异/回滚、适配器医生和可解释本地质量证据。
更新只替换受管程序文件；来源、评分、标签、备注、设置与 SQLite 会继续保留。

## Highlights

- Spectral Gravity rebuilds the homepage around true circular source, parent,
  and child nodes, real relationship focus, adaptive LOD, and reduced-motion
  fallbacks.
- Smart metadata recognition reads bounded local `README` and `SKILL.md`
  evidence to propose editable summaries, purposes, usage guides, categories,
  and custom tags.
- Source staging now produces per-file security findings. High-risk findings
  block promotion; medium-risk findings stay isolated with redacted evidence
  until the user explicitly confirms the review. The backend repeats the gate
  before any managed-source or Agent-link write.
- Adapter Doctor explains desktop-app detection, local Code capability, PATH,
  Skills-directory readiness, and stale residues separately.
- Recoverable v4 migration resumes per-source copies, validates content before
  promotion, backs up SQLite, and preserves newer destinations and manual
  metadata.
- Git-backed sources can pin their current commit, preview an upstream update
  diff, and roll back to the latest verified backup. Rollback first preserves
  the current complete tree and records an audit event.
- A local 0–100 quality signal uses up to four independent evidence types:
  personal/child rating, indexed health, recorded local use, and security
  scanning. Missing evidence is excluded and fewer than two evidence types do
  not produce a headline score. GitHub stars remain popularity only.
- The legacy cleanup assistant lists only allowlisted old portable locations
  after v4 migration and SQLite health checks pass. A confirmed cleanup moves
  the selected data to a recoverable backup; it never selects `release`.
- The desktop shell now uses a strict CSP and least-privilege capabilities.
  Release binaries are stripped, path-remapped, and checked for developer
  paths; the portable package uses an explicit document allowlist.

## Upgrade

Users already on v3.0.3 can install v3.0.4 through the signed in-app updater.
Users on v3.0.2 or older need to install the current signed NSIS setup once.

Program files are replaced in place. Sources, ratings, tags, notes, settings,
and SQLite remain under:

```text
%LOCALAPPDATA%\AI SkillHub\UserData
```

Legacy portable data is copied and verified without deleting the original.
Confirm the recovered source count, Skill count, ratings, notes, and tags
before using the cleanup assistant. The verified local recovery restored 38
managed sources and 650 indexed Skills from the 38-source / 649-Skill legacy
database. The one additional Skill is a real duplicate path inside the same
source exposed by the current, more complete scan. Ratings, tags, manual
metadata, and use records were preserved. “0 local” is correct because the
legacy `skills` entries are managed links, not standalone local sources.

Migration v4 now serializes concurrent startup scans and refuses to finalize a
partial run. Its verified manifest completed with `failed: 0` and
`repairNeeded: 0`. The developer `release` directory stays outside automatic
cleanup and remains a manual decision.

## Boundaries

- Metadata recognition is offline and does not execute source scripts.
- Evidence completeness is not a quality score.
- GitHub stars and the local quality score remain separate signals.
- Pin, diff, and rollback apply only to sources with usable Git history.
  Network failure may show a cached diff; rollback is unavailable until a
  verified backup exists.
- The current Canvas 2D renderer uses 650/1200-node LOD, adaptive frame work,
  background pausing, reduced-motion behavior, and a static fallback. WebGL is
  a future optional renderer, not a v3.0.4 dependency.
