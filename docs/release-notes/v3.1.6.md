# AI SkillHub v3.1.6

v3.1.6 repairs Skill classification around the real parent-child source tree
and makes sync and update results match what actually happened.

## Folder classification

- Drag the handle on a source card into a folder, or choose a folder from the
  source card/editor. The parent Skill and every child Skill move together.
- A child Skill sourced from a repository inherits its parent's folder and is
  not independently draggable. Standalone Skills remain independently
  classifiable.
- Folder cards now include visible edit, reorder, and delete controls. Deleting
  a folder only removes its classification; it never deletes Skill files.
- Eight named color swatches use fixed color tokens and visible selection rings
  across dark and light themes.
- Large source trees render progressively to avoid opening hundreds of complex
  rows at once.

## Exact source ownership

- Every indexed Skill carries an exact `sourceId`.
- GitHub repositories use an owner-qualified storage name such as
  `emilkowalski--skills`, preventing a generic repository name from colliding
  with another local `skills` directory.
- Legacy fuzzy path matching no longer attaches unrelated child Skills below a
  source card.

## Honest status and updates

- The dashboard mode is now “My folders”. Unclassified entries appear under
  Unfiled and are not silently grouped by inferred type.
- Sync reports complete, partial, failed, or local-only outcomes. Repositories
  containing uncommitted or untracked work are left untouched and reported.
- Evidence chips distinguish strong, mixed, insufficient, and weak evidence.
  Version chips show the current short commit and whether the source is current,
  behind, locally ahead, diverged, pinned, or waiting for a network comparison.
- The signed updater checks GitHub Releases plus two manifest fallbacks after
  startup, after resume, and when the network returns. Publishing the v3.1.6
  installer and generated manifests makes older installed builds discover it.

## Upgrade safety

The active tracked source is updated in place, while verified previous Git
revisions remain recoverable through internal backup refs. User data lives in
the independent application data directory and is retained by installer
upgrades. Dirty local work is never overwritten by ordinary synchronization.
