# AI SkillHub v3.2.0

## 中文说明

v3.2.0 在不改变既有界面与核心流程的前提下，修复刷新和来源编辑时的卡顿：同步只运行一份后台任务，
来源备注与标签一次事务保存，更新检查单通道最多等待 8 秒；Git 来源按持久化游标轮转，预算延后的
来源会在下次优先检查。核心索引完成后只合并轻量 GitHub 热度卡片，不再读取第二份完整快照。

- 正常启动先从 SQLite 显示 Skills、来源和文件夹，再在不锁住界面的后台补齐 Agent、治理和诊断卡片；
  首次安装、索引缺失或损坏时仍会执行一次必要扫描。
- 六点手柄只负责拖动，文件夹下拉只负责选择，并在深浅主题下保持可读。
- 折叠状态下的父 Skill 和展开后的每个子 Skill 都有精确名称复制；Claude Code、Codex 等宿主仍只接收每个来源的唯一父入口，
  不制造数百个冲突的全局子别名。
- 修复大小写不一致、断 junction 和合法多行 YAML 简介导致 Claude Code 漏识别的情况；不安全或超长的来源名会生成带稳定哈希后缀的合规父名称，避免规范化碰撞。
- 首页画布只在入场和交互时重绘，静止后自动休眠；拖动和缩放仍即时唤醒。高 DPI 画布使用硬像素预算，
  避免窗口空闲时持续占用 GPU。
- MCP 连接中心可为受支持的 Codex/Claude binding 预览、添加、重配、删除和回滚。待确认计划只保存目标指纹和脱敏差异；
  为保留原配置及支持回滚，配置文件中已有的内联值会在进程内短暂解析，并仅随原配置写入当前 Windows 用户 DPAPI 加密的私有回滚快照。
  软件不启动 MCP Server、不读取环境变量中的凭据值，也不在界面、诊断或返回结果中显示凭据值。写入后请重启宿主并用 `/mcp` 验证实际运行状态。

## English

v3.2.0 keeps the existing interface and workflows while making refreshes more responsive, repairing Claude Code and Codex delivery, and adding reversible MCP configuration management.

## Highlights

- Refresh is single-flight, source notes and tags save in one small background operation, and GitHub popularity follows as a lightweight card merge instead of a second full snapshot.
- The normal desktop launch paints its compact SQLite index first, then hydrates deferred Agent, governance, and diagnostic cards without replacing the visible library or locking navigation.
- Browser-only fixture data is split from the desktop startup path, reducing normal startup parsing while keeping the preview unchanged.
- Bounded Git refreshes now remember the first deferred source and start there next time, preventing the same repositories from being starved by a fixed alphabetical order.
- Native WebView file-drop interception no longer blocks source-tree drag/drop. The drag grip and folder selector are separate controls, folder selectors follow the active theme, and both collapsed parent Skills and expanded child Skills expose exact-name copy actions.
- Dashboard canvases animate during entry and interaction, settle to zero idle redraws, and keep a hard high-DPI pixel budget.
- Claude Code and Codex receive one lowercase parent route per source, with broken links and valid multiline YAML descriptions handled correctly.
- Codex and Claude Code MCP changes show a redacted diff before confirmation, write atomically, verify by reading the configuration back, and can roll back to the saved snapshot.

## Important boundaries

- Child Skills still run through their parent route; AI SkillHub does not publish roughly 910 separate child aliases. Copying a child name makes it easier to specify the intended capability after selecting its parent.
- AI SkillHub never starts an MCP server, does not read credential environment-variable values, and does not return, log, or display credential values. Existing inline values in a host configuration are parsed briefly to preserve the file and are retained only inside the private rollback snapshot protected with the current Windows user's DPAPI key. The confirmation journal keeps target fingerprints and redacted evidence only. Claude JSONC files containing comments or trailing commas remain read-only.
- Unconfirmed MCP request data expires after 15 minutes and is bounded to 64 plans or 8 MiB in total; an apply attempt consumes its in-memory plan on either success or failure.
- Rollback payloads live only in private app state, are protected by the current Windows user's DPAPI key, remain discoverable after restart, and are pruned after seven days or at 16 snapshots / 128 MiB. They are never placed beside host configuration files.
- If Codex, Claude Code, or another program changes a target after preview or after apply, AI SkillHub refuses to overwrite it during apply or rollback and asks for a fresh plan.
- Codex bindings can be enabled or disabled in AI SkillHub. Claude Code keeps enablement as per-project host state, so use Claude Code's own `/mcp` panel for that toggle.
- After an MCP change, restart Codex or Claude Code and use `/mcp` in that host to confirm that the server is available at runtime.

The fallback updater manifest is published only after the matching release assets have been publicly downloaded and verified with the updater's embedded public key; until then, the last verified stable manifest remains unchanged.
