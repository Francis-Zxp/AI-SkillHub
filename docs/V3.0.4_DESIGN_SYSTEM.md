# AI SkillHub v3.0.4 — Spectral Gravity Design System

## Product split

AI SkillHub deliberately uses two visual tempos:

- **Dashboard / brand scene** — an expressive, full-viewport capability universe.
  It should make the size and structure of a real Skill library understandable
  before the user reads any copy.
- **Working screens** — quiet, high-contrast application UI. Library, routing,
  AI-tool and settings screens prioritize scanning, editing and diagnosis.

The dashboard is the portfolio moment. The rest of the product is the daily
tool. They share typography, spacing, colour tokens and motion curves, but they
do not pretend every screen is an art installation.

## Spectral Gravity

Every visible effect in the capability universe has a data meaning.

| Visual signal | Product meaning |
| --- | --- |
| Node position | category cluster and parent/child attraction |
| Cluster colour | Skill category |
| Source diameter | logarithmic GitHub popularity plus child count |
| Router double ring | generated parent/router Skill |
| Five ring segments | the user's local 1–5 rating |
| Child point | an installable folder containing `SKILL.md` |
| Hollow point | disabled or unavailable Skill |
| Connection line | real source, parent/child or conflict relationship |
| Slow pulse | selected or hovered relationship neighbourhood |

Shapes are drawn in screen space. A circular node must remain a circle at every
window ratio and DPI; projection depth may change its diameter, never its
aspect ratio.

## Palette

The palette is spectral, not rainbow noise. Category hues are separated enough
to survive the dense overview while sharing similar luminance.

| Category family | Colour |
| --- | --- |
| Research | `#59A7FF` |
| Literature | `#62E6B2` |
| Engineering | `#9B7CFF` |
| Data | `#B4E85A` |
| Image | `#FF68C7` |
| Security | `#FF706A` |
| Documents | `#FFC55C` |
| General | `#A7B4D7` |

The dark scene uses near-black neutral surfaces instead of green-tinted panels.
The light scene uses cool paper-white surfaces. Saturated colour belongs to
data and active state, not to every container.

## Motion

- Initial formation: `650–900ms`, opacity and position together.
- Camera zoom: critically damped interpolation, never direct wheel jumps.
- Mode morph: `420ms`.
- Hover response: next animation frame; only the hovered neighbourhood brightens.
- Idle drift: below `1°/s`; cluster breathing stays below `3%`.
- Dragging suspends expensive ambient effects and prioritizes camera response.
- `prefers-reduced-motion` freezes idle motion and keeps selection feedback.

## Rendering budget

| Level | Node count | Behaviour |
| --- | ---: | --- |
| LOD 0 | up to 649 | full rings, highlights and relationship detail |
| LOD 1 | 650–1199 | simplified child nodes and reduced ambient links |
| LOD 2 | 1200 and above | sampled lightweight child points and selected-neighbour detail |

The renderer adapts device-pixel ratio, shadow work, line count and animation
quality to measured frame time. It must retain a static accessible view when
animation or GPU acceleration is unavailable.

Acceptance data sets: 115, 650, 1200 and 2500 nodes. At 100%, 125%, 150% and
200% display scaling, the measured width/height difference of every circular
node must be at most one physical pixel.

## Working-screen rules

- Default body copy is at least 14px at the normal density setting.
- Secondary text must meet WCAG AA contrast; low contrast is not hierarchy.
- One spacing system and one alignment grid are used across all pages.
- Containers do not alternate arbitrarily between sharp and rounded corners.
- Borders are reserved for boundaries and input affordances, not decoration.
- Icon optical size is normalized; repeated actions use the same icon box.
- Long diagnostics start with a one-line outcome and reveal evidence on demand.
- Advanced release, QA and snapshot executors stay out of beginner settings.

## Reference principles

The system studies, but does not copy, FIELD's data-authentic spatial work,
Linear's calm application hierarchy, Figma's infinite-canvas performance work,
Sigma's neighbourhood interaction model and modern GPU particle rendering.
The transferable principle is consistent: the spectacular layer comes from
real structure and excellent response, while the interface around it becomes
quieter.
