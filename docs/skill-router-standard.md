# AI SkillHub Parent Skill Router Standard

This document is the stable rule for parent/child Skill routing in AI SkillHub.

## Product Model

A source repository is one management and invocation unit. AI SkillHub publishes
one canonical parent Skill for every non-empty Skill source, including sources
that contain only one Skill. Users call the parent; the parent selects a child
inside its own source.

Codex, Claude and Antigravity currently enumerate a flat top-level Skill list,
so AI SkillHub does not pretend that native nested menus exist. It publishes the
canonical parent entry and writes the child capability list into that parent's
`SKILL.md`. The Skill Library may render the same relationship as a tree.

## Markers

- `[ROUTER-HUB]`: the stable machine marker for a parent Skill generated by AI SkillHub.
- `[CHILD-SKILL]`: a child capability listed inside its parent.

Markers remain ASCII-only to survive Windows PowerShell, Git, YAML parsers and
cross-machine copies. `[ROUTER-HUB]` lives in an HTML comment so Agent parsers can
identify the parent without showing a technical token to users. The visible
frontmatter description and heading use the concise localized label `父 Skill`.

## Generation Rules

1. Generate routers only under `%LOCALAPPDATA%\AI SkillHub\UserData\sources\AI-SkillHub-local-routers`.
2. Never modify author-owned `SKILL.md` files.
3. Generate exactly one canonical parent for every enabled, non-empty source.
4. Keep the parent callable by the normalized original source name, such as `/figures4papers`.
5. Keep the visible frontmatter description machine-safe and concise; it must not begin with a bracket token.
6. Include `[ROUTER-HUB]` once in an HTML comment and use `父 Skill` in the visible description and heading.
7. List every child as `[CHILD-SKILL]`, with its exact source-scoped `SKILL.md` path and a concise localized function summary.
8. The parent may load children only from its declared source. It must never substitute a same-name child from another source.
9. Rebuild parents after startup repair, adding a source, manual sync and automatic update.
10. Generated writes are recoverable: write a temporary file, preserve the previous generated file, then activate the replacement.

## Same-Name Children

Same-name children in different sources are not a user decision. Their parent
source is their namespace. For example, each parent may contain a
`figure-planner`, but `/nature-paper-skills` can only load the one declared under
Nature-Paper-Skills and `/paperspine` can only load the one declared under
PaperSpine.

AI SkillHub no longer generates global `[CONFLICT-DISPATCHER]` Skills or asks the
user to select a default child. Existing generated dispatchers are removed during
repair. Historical SQLite choices are retained only for rollback compatibility.

## Agent Delivery Contract

1. Codex, Claude and Antigravity receive the same curated allowlist.
2. Publish generated parent entries instead of flooding the recipient with every child directory.
3. Keep truly standalone/local Skills visible when no parent exists.
4. Never create a fake Agent directory when that Agent is not installed.
5. Preserve user-owned folders and external links; only replace links previously managed by AI SkillHub.
6. Validate that every published entry contains `SKILL.md`.

## Skill Library Contract

The primary card shows the source/parent name, personal parent rating, localized
purpose, child count, folder, health, enabled state and edit action. Commit hashes, evidence scores and
raw maintenance metadata stay out of the primary card. Update, rollback and
diagnostic details remain available in maintenance surfaces when needed.
