# v3.2.17 review and release verification

## Scope and findings

The recipient can reinstall 3.2.15 on the same PC where Smart App Control blocks 3.2.16. Five original installers were compared: all lack Authenticode, and their NSIS `.text`, `.rdata`, and `.data` sections are identical. The 3.2.15-to-3.2.16 build scripts and dependency versions did not change. This supports a file-specific classification/payload difference, not a proven universal certificate-only cause. Version renaming does not establish Windows acceptance.

Two updater defects were fixed using a bounded vendored patch to the already locked 2.10.1 crate:

1. `ShellExecuteW` launch failures no longer trigger window/resource cleanup or process exit. Cleanup occurs only after successful launch. Failure codes and a real Windows missing-installer launch are regression-tested, including a later successful retry callback.
2. The webview check command no longer accepts `allowDowngrades`, preventing frontend arguments from replacing the native forward-update policy.

The application now displays installation-specific failure guidance rather than the generic update-channel message. Download signature verification, HTTPS validation, installer arguments and existing dependencies are retained. Upstream licenses and a patch description ship in both distribution formats. `app-next/vendor/tauri-plugin-updater/PATCH.md` records the upstream base and removal conditions.

Review focused on update verification/lifecycle, GitHub import and path handling, external Skills boundaries, MCP transactions and host delivery. Existing regression tests exercise traversal/link refusal, local-edit preservation, rollback/recovery, malformed configuration and client detection. This was not a claim of an exhaustive penetration test or zero remaining bugs.

## Completed source checks

- Rust library: 291 passed, 14 intentionally ignored.
- Rust integration: 66 passed, 2 intentionally ignored; the separate opt-in release artifact gate is run after packaging.
- Patched updater: 5 passed, including 2 Windows lifecycle regressions.
- Frontend contracts: 170 passed.
- TypeScript, Rust formatting and clippy: passed.
- Six PowerShell suites: sync resilience, diagnostic-index integrity, parent routing, Codex, Claude Desktop and WorkBuddy delivery passed.
- Production frontend dependency audit: 0 reported vulnerabilities across 7 dependencies. This does not constitute a Rust advisory audit or future vulnerability guarantee.

## Distribution policy and cleanup

The user authorized a formal 3.2.17 release despite not having a Windows publisher certificate. Formal packaging requires an explicit `-AllowUnsignedPublicRelease` option to disclose this condition; default Authenticode checks and mandatory Tauri update signatures remain. Local-only candidates cannot publish the fallback manifest. No Windows security setting is changed.

The 3.2.16 draft release, attachments and tag were deleted after saving metadata locally. Its release notes and review were archived locally; current README links and changelog now describe 3.2.17. Historical Git commits are preserved.

## Acceptance limits

- Old installed versions still use their old updater to initiate the first upgrade. This lifecycle fix is active after 3.2.17 is installed.
- Successful process launch is not proof that an installer or a child process completed successfully.
- The recipient's Smart App Control decision on the new binary still needs real-device confirmation. No Microsoft file review has been submitted on the user's behalf.
- WorkBuddy host invocation and recipient-specific Claude environments remain subject to their actual client setup; fixture tests do not establish all-host acceptance.

Artifact hashes, installation checks and final publication identifiers are appended after verification.
