## Problems found by release checks

The first full Windows run exposed an atomic MCP replacement failure. Adding the OS error code identified code 3; a new local test with a path over 260 characters reproduced it. Direct Win32 replacement now receives normalized native long paths, consistent with the Rust filesystem operations that created the file. Four regression cases pass: long paths, a released sharing lock, a persistent lock, and an external edit during the wait. Temporary files are closed before replacement; retries remain bounded and recheck the target fingerprint.

A later concurrent runner timed out the fake MCP handshake test. That test now allows 60 seconds for the functional protocol/cleanup checks, while the application's 20-second limit and the separate injected-deadline test are unchanged. Windows CI uses two test threads to reduce subprocess/ACL-tool contention. These last changes affect tests and CI only; the validated runtime artifact was not replaced again.

## Local cleanup scope

The reviewed plan removes only reproducible build caches, obsolete release outputs, and duplicate old release downloads. It includes three `target-v33-*` directories and this project's mapped external Cargo debug/release/tmp cache. Paths are checked before deletion; the plan contains no reparse points or tracked source files. Current 3.3.0 artifacts, Git history, personal Skills/configuration, reference source material and user-state backups are retained.

Plan: `reports/cleanup-plan-20261015.json`; result: `reports/cleanup-result-20261015.json`. Old public verification metadata is retained separately before removing duplicated binaries. Cleanup requires successful public release verification. Protected source/runtime/configuration/database hashes are checked before reopening the app.
