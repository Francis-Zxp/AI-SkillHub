# AI SkillHub v3.2.5 实施与验收记录

日期：2026-09-20。当前为本地候选版本；线上已发布版本仍为 v3.2.4。

## 1. 阴影问题的结论

用户两张截图显示：深色主题在侧栏、顶栏、控制组和底栏周围出现白色大片光晕，浅色主题同位置出现黑灰阴影。提供的 7.205 秒视频中可读版本号为 **3.2.4**，顶栏下方的灰色带仍存在，支持“旧修复没有解决”的反馈。

这些条栏属于 DOM/CSS，不是星图 Canvas。3.2.3 改动 `SkillUniverse.tsx` 的 atmospherePalette，与截图中条栏的独立阴影没有直接对应关系。`styles.css` 中仍存在 44–80px 的大模糊、以主题背景色混合生成的阴影，以及多层 `backdrop-filter`。后置主题规则还会覆盖早期设置。

本轮将条栏阴影改为显式 RGBA，模糊范围控制在 8–16px，取消侧栏大阴影、标题大范围文字阴影及这些条栏的背景模糊依赖。保留原有主题、星图与操作布局。

**证据边界：**可确定旧修复错层以及本轮已移除造成大片条栏阴影的 CSS 依赖；没有朋友电脑的 WebView2 版本、GPU/驱动和实机复测，不能把“某驱动或某浏览器缺陷”写成已经证实的根因，也不能保证所有电脑都已验收。

视觉证据：`app-next/reports/visual/v3.2.5-chrome-shadow/`。36 组生产 CSS 隔离测试及 36 组完整应用测试通过，覆盖六种 Atlas 主题、DPR 1/1.25/1.5、默认及 `--disable-gpu`。浏览器为本机 Edge 153.0.4234.48；禁用 GPU 参数不等于复现朋友机器的 GPU/软件渲染栈。

## 2. 外部 Skills 管理流程

新增 **AI 工具 → 本机 Skills**：

1. 只读扫描已有客户端技能根目录，展示客户端、用户/项目范围、真实路径、目录/链接和管理状态。
2. 输入项目绝对路径，扫描约定的 `.agents/skills`、`.claude/skills`、`.cursor/skills` 等目录，不递归搜整块磁盘。
3. 搜索、工具筛选、管理状态筛选，按 60 条递增展示。
4. 读取原始 SKILL.md，始终按文本显示，限制 256 KiB，不执行 Markdown 中的代码或 HTML。
5. “纳入技能库”预填现有本地导入流程。已有草稿先保留，由用户明确选择使用新路径；仍经过隔离复制、安全扫描与原有写入授权。

发现不要求 Skill 必须由本软件安装，也不会创建不存在的客户端目录。目录存在仅证明有技能文件，不等于证明客户端程序已经安装或支持该 Skill。

**本版边界：**管理的是独立副本。原件与副本没有自动双向同步；复制后原件仍作为外部路径存在。插件缓存、外部原件的删除/直接编辑、批量冲突合并不在本版范围。链接到 SkillHub 受管理目录的项目会标记为已管理。不同客户端的同一真实路径保留各自可见记录，因此条目数不等于去重后的技能数。

实现文件：`external_skills.rs`、`ExternalSkillsPanel.tsx`、`ExternalSkillsPanel.css`、`externalSkills.ts`，桥接位于 `lib.rs` 和 `App.tsx`。

## 3. 同步与导入缺陷

- **同长度更新漏检：**原快照指纹只记录路径与文件大小；改为逐文件 SHA-256，测试覆盖同长度内容替换。
- **本地修改可能被覆盖：**新下载记录 baseline；当前树不匹配基准时跳过，保留修改。旧快照缺少基准时，只有本地与新下载完全相同才自动建立可信基准。
- **本地导入路径别名绕过：**用 canonical 路径校验来源，拒绝指向 SkillHub 私有运行目录的别名。
- **内部链接与读取失败：**合法外部 Skill 根链接可读取和复制；内部 junction/链接不能悄悄跟随或漏复制，读取失败不再被吞掉。
- **扫描后筛选失效：**新结果不含此前选中的工具时重置筛选，避免下拉看似“全部”而结果为空。

## 4. 删除与跨盘移动恢复

- **删除顺序：**原实现存在“已移动来源、配置或索引写入失败”的中间窗口。现在先把来源移到可恢复备份，计算配置删除计划，并以同目录暂存文件替换配置；投递重建失败时，恢复配置字节和来源位置，再重建一次投递。
- **跨盘复制：**直接复制到最终备份目录会在失败时留下可被误判为完成的混合树。现在复制到隐藏的同目录暂存目录，逐文件 SHA-256 对比后用同卷 rename 激活，最后才删除原目录。
- **故障状态：**激活前失败不会出现最终目标；原目录清理失败时，两个完整目录均保留并在错误消息中给出路径。既有目标目录会被拒绝，绝不覆盖。

该恢复边界覆盖来源、运行配置、SQLite 索引和 Agent 投递的一致性；用户手动删除或磁盘/权限故障的真实恢复仍需要桌面实机操作验证。

## 6. 下一步的执行顺序

先用 3.2.5 候选包在朋友电脑覆盖安装，验证两种主题、窗口拖动/缩放、最小化恢复和页面切换。记录设置显示的版本号及新截图；无需先卸载。若异常仍在，再采集 WebView2/显卡/驱动与显示缩放证据，避免继续盲改 Canvas。

随后按 `v3.2.5-reference-audit.md` 的阶段任务推进：项目工作区持久注册、分发矩阵、冲突预览优先于市场和双向同步。该报告列有五项目的具体源码依据、许可证和可直接交给执行模型的任务模板。

为节省 token，本轮由主代理整合，三个独立子任务分别负责绘制修复、外部发现、安全与参考审查；统一执行 Cargo 门禁，避免三个模型重复编译或重写同一功能。后续给每个模型一个限定模块、固定接口和验收清单即可。
