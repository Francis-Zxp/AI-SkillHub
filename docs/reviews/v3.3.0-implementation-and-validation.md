# AI SkillHub v3.3.0 实施与验收记录

日期：2026-10-08。分支 `claude/v3.3-experience-overhaul`，基线 `7b71c94`（3.2.18 发布）。

用户 2026-10-07 的要求：

- 查项目里的 bug 并修复；
- 设计几种随机群岛的不同地形和天气；
- 以 xingkongliang/skills-manager 和一个人气 MCP 管理工具为榜样，大刀阔斧地改，让用户用最少的操作就能让多个 AI 工具接管并使用 Skills 和 MCP；
- 运行内存从约 300 MB 降到最多约 80 MB，同时不损失现有的交互和显示效果。

本次是**本地候选**：签名构建，在本机安装。没有推送，没有公开发布，公共更新清单不变。

## 一、过程

1. **研究与审计**
   - 榜样：skills-manager v1.40.3（5,655 星）和 CC Switch v4.0.3（140,564 星，MCP 榜样，同样是 Tauri 2 + Rust + React + SQLite）。两者都是只读研究，没有复制代码。
   - 对 Skills 和 MCP 两条体验路线做了 UX 审计，结果合成改造简报。输入材料存在 `reports/v3.3-work/`。
2. **Bug 普查**：前端外壳、Rust 核心、MCP、视觉四个方向分头查找，每条都经过对抗式复核。确认 50 条，驳回 1 条。另外简报里列了 42 条 UX 问题。
3. **契约**：`docs/v3.3/skills-contract.md` 和 `docs/v3.3/mcp-contract.md`，让前端和后端可以并行开发。
4. **结构重构**：App.tsx 从 8,129 行拆成多个页面模块，行为不变（`d20c3b8`）。经独立复核，226 条顶层语句逐字一致，9 个视图渲染一致。
5. **五条实现线**，各在独立的 worktree 里开发，各有独立复审：
   - Skills 后端
   - Skills 前端
   - MCP 后端
   - MCP 前端
   - 天空岛
   
   之后由协调者合并，并完成内存改动和集成。

## 二、主要变化

**外壳与流程**

- 侧栏显示文字，AI 工具各列一行；顶栏有 Ctrl/⌘+K 搜索、"+ 添加"、"更新 (N)"和同步状态点。
- 首次运行先引导，征得同意前不往任何客户端目录写入。
- 每个工具的接管开关和全局暂停都由后端执行。
- 去掉了不起作用的授权药丸和工作区页面。
- 界面用语改为"技能 / 技能包 / MCP / AI 工具"，并加了禁用词测试。

**Skills**

- 投递单位改为"技能包 × AI 工具"，新增 agent_skill_targets 表；每个技能包一排工具图标，状态以读回磁盘的结果为准。
- 投递在后台去抖、合并执行，PowerShell 5.1 契约保留，不再锁住界面。每个工具单独报告结果。
- 关掉的子技能会从父路由里移除。
- 一个输入框完成导入：可以预览、勾选技能、选择工具；被标记的来源仍只能加入技能库并保持停用。
- 外部技能可以一次批量纳入管理。
- Cursor 和 Gemini CLI 作为实验性目标加入，默认关闭。
- 同名的个人目录只报告为冲突，不再移走。

**MCP**

- MCP 库（敏感部分用 DPAPI 加密）加上"服务器 × AI 工具"矩阵，覆盖 Codex、Claude Code、Claude Desktop、Cursor。
- 点一个格子就直接写入，并给出撤销。删除、外部改动、覆盖同名配置、回滚、内联密钥，仍然要人话确认。
- 粘贴解析器支持 JSON、TOML、VS Code、OpenCode 格式，由粘贴、导入和 GitHub 导入共用。
- 密钥写进 HKCU 用户环境变量，配置里只留引用。
- 测试连接由用户点击才运行，先显示命令。
- 每个工具单独报告结果，历史记录用人话写。
- Windows 上 `cmd /c` 的包装规则改对了；Claude 的 JSON 键保持原有顺序；带注释的 JSONC 文件保持只读。

**天空岛**

- 八种地形气候、九种天气，"世界"面板里可以换一个世界或固定天气。
- 修复视觉 bug #36–#49。
- 合并村民和动物的网格：14 岛预览的绘制调用从 329 降到 218。

**内存**

- `memory_saver.rs`：最小化时隐藏 WebView 控制器并设 MemoryUsageTargetLevel=Low；失焦 20 秒后设 Low，每 4 分钟重设一次；恢复时改回 Normal。同时通知页面。
- tauri.conf：保留 Tauri 默认开关，另加 NetworkServiceInProcess2 和 `--js-flags=--max-semi-space-size=2`。
- 3D 场景看不见超过 15 秒就休眠成一张静态图，GPU 资源清零，唤醒约 0.15–0.4 秒。
- 每帧分配量从 9.8 MB/s 降到 1.9 MB/s；在 DPR ≥ 1.5 时不再用 MSAA，像素预算降到约 3.7 M。

## 四之二、试用反馈后的布局调整（2026-10-09）

用户反馈：功能比以前强，但布局、观感和直观性不如 3.2.x。本次在保留新功能的前提下改回旧布局。

**首页与外壳**

- 首页回到 3.2.x 布局：场景铺满页面，四个数字和"发现工具 / 添加"放在底部栏，不再遮挡数据球。底部栏换行时高度会变，群岛的说明、素材与许可、分类导航、归纳卡片都按底部栏的实测高度定位。
- 首页场景改为"群岛 / 星图 / 归纳"。"归纳"就是旧版的分类聚类视图；本地保存的 off 会迁移为 summary。
- 侧栏改回细长的图标条；顶栏恢复语言切换、主题切换和 GitHub 按钮。
- 删除现代、经典各两个主题，设置里铺开列出全部主题。

**技能库与菜单**

- 每一行先显示用户自己写的备注（窗口窄时放到名称下方），并在行上直接提供"复制调用名"。
- ⋯ 菜单改为渲染到浮层并固定定位，不会再被卡片裁切；用键盘打开时焦点进入菜单。

**调用名 bug**

- 过去复制出来的是内部索引名"包__子"。现在由后端 skill_call_name 计算：单技能包复制父入口名，包内子技能复制"父入口 子技能名"。
- 用真实库核对：996 项里没有一项还带 __；每个父入口都对应 ~/.claude/skills 里的一个入口。唯一的例外 oil-ui--oil-oil 是被安全检查标记、保持停用的技能包，没有入口是正常的。

**验证**

- tsc 0 错误；node 240/240；cargo lib 434 通过，其余测试组 82 通过，clippy 和 fmt 干净。
- 体积：JS 573,028 B，CSS 161,543 B。
- 浏览器 QA：Skills 15/15、MCP 24/24、天空岛 34/34。
- 截图在 reports/v3.3-work/layout-v2、layout-860、layout-1920。

## 五、边界与未完成

- 80 MB 的目标只在最小化时完全达到，失焦或闲置时接近；前台正在使用 3D 时达不到。原因是 WebView2 空白页本身就约 150 MB，这是实测。
- Cursor 和 Gemini CLI 没在真机应用里验证，仍标"实验性"。
- MCP 的真机手动检查 D1–D11 待完成，包括 Claude Desktop 和 Cursor 的实际连接。
- 带空格的绝对路径命令再遇到带空格的参数时，`cmd /c` 的引号行为需要真机确认。
- 两项早先被自动安全审查拦下的改动，本次没有做：一键加载不受安全扫描拦截、技能库默认不展开子技能。
- 遥测保持默认开启，但已在设置里写明，并提供关闭开关。
