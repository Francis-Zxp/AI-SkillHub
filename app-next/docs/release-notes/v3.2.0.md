# AI SkillHub v3.2.0

This release preserves the established interface and core workflows while removing the main refresh stalls, strengthening parent-Skill delivery, and turning the MCP Connection Center into a reversible configuration manager for Codex and Claude Code.

## Faster everyday work

- Refresh is single-flight and follows the core index update with only a lightweight popularity-card merge, not a second full snapshot. Users can continue navigating during read-only work; conflicting write actions share one visible busy state.
- A source name, note, category, enabled state, and tags now save through one background transaction with a compact response.
- Each update-channel request has an eight-second limit and the foreground check no longer repeats a second retry cycle. Pointer glow updates are coalesced into one animation frame to avoid repeated layout work.
- Browser-only fixture data now loads on demand, reducing the JavaScript parsed during normal desktop startup without changing the preview.
- Bounded Git refreshes use a monotonic deadline, reserve one complete manual-repository attempt, and persist a rotation cursor. Cursor failures are visible but non-fatal, and a fixed alphabetical tail cannot starve indefinitely.
- The drag grip only drags, while the adjacent folder selector only opens the accessible folder list. Native selectors and folder surfaces remain readable across themes.
- Every child Skill has a keyboard-accessible button that copies its exact name without opening the row or folder selector.

## Reliable Claude Code and Codex delivery

- Generated parent invocation names are canonical lowercase names on every recipient. Unsafe or overlong source names receive a stable hash suffix so two lossy normalisations cannot overwrite one another.
- Delivery repairs stale links, validates parent and child files, and accepts valid multiline YAML descriptions instead of silently excluding them.
- The shared catalog remains parent-first. Child Skills are listed and selected through their parent route; this release does not publish roughly 910 global child aliases. The child copy button supplies the precise capability name to use after choosing the parent.

## Safe MCP configuration changes

- The MCP Connection Center can plan add, update, or remove operations for supported Codex and Claude Code scopes.
- Every change follows `plan → redacted field diff → explicit confirmation → atomic write → static read-back verification`.
- A successful batch creates a rollback snapshot that remains discoverable after an app restart. If any target in a multi-host batch fails, every already-written target is restored before an error is returned.
- The encrypted manifest is persisted before the first host write and records each transaction state. Restart recovery restores only files matching recorded fingerprints; unknown external content is never overwritten.
- Rollback payloads are kept only in private app state, protected with the current Windows user's DPAPI key, and pruned after seven days or at 16 snapshots / 128 MiB. No backup is written beside a host configuration file.
- Unsafe paths, symbolic links, stale plans, concurrent file changes, malformed configuration, and secret-bearing input are rejected. A target changed externally after apply is also refused during rollback rather than overwritten.
- Ordinary command, URL, and argument fields remain in process memory only during confirmation. The bounded on-disk plan contains only target fingerprints and redacted diffs—not those raw fields—and the complete journal is encrypted for the current Windows user. Credential references accept environment-variable and header-reference names, while obvious inline credential patterns are rejected. Existing inline values are not exposed through diffs, plan journals, diagnostics, or command results.
- The in-memory plan cache expires entries after 15 minutes and is capped at 64 plans and 8 MiB of request data. Applying a plan consumes it on both success and failure; a restart or expired plan therefore fails closed and requires a new preview.
- Claude files using JSONC comments or trailing commas remain visible to the scanner but read-only to the mutation path.
- Codex bindings can be enabled or disabled here. Claude Code stores enablement per project outside the binding, so its toggle remains in Claude Code's own `/mcp` panel; AI SkillHub does not write an unsupported `disabled` field.

AI SkillHub still performs no capability probe and never launches an MCP process. After applying a change, restart the affected Codex or Claude Code host and use `/mcp` there to verify that the configured server can actually start and respond.

## Release verification

- Frontend behavior contracts cover single-flight refresh, compact source saves, folder interaction separation, exact child-name copying, bounded update checks, animation-frame glow work, and the bundle budget.
- Rust and integration contracts cover MCP plan/apply/rollback, redaction, JSONC refusal, concurrent-change refusal, multi-host restoration, scanner read-only guarantees, and parent delivery.
- Every formal publication requires installer and portable-package checks, updater-signature verification, upgrade preservation, a fresh-recipient workflow, public re-download, and update-channel verification.
