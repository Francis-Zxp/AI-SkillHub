状态：Checkpoint 1，等待 Francis 确认后再进入可运行 v0。

工作分支：`codex/v3-kinetic-lab`

## 1. 设计任务判断

本轮属于 **Redesign · Overhaul**，不是换一组颜色。产品数据、Tauri 命令、SQLite、本地评分、来源同步、安全边界和 AI 工具适配属于受保护契约；信息架构、视觉层级、页面布局、动效系统和冲突处理体验允许重构。

设计定位：面向科研与工程用户的“AI 能力观测站”，把来源、父 Skill、子 Skill、Prompt、Agent 和路由关系呈现为可操作的动态地图，而不是又一套紫蓝色 SaaS 卡片。

五个设计旋钮：

| 维度 | 目标值 | 理由 |
|---|---:|---|
| 视觉差异度 | 8/10 | 需要明显脱离 2.x，但保留品牌和任务语义 |
| 动效强度 | 8/10 | 用户明确希望粒子、互动与创意奖级体验 |
| 信息密度 | 8/10 | 当前约 656 个 Skill、132 组冲突，不能用低密度营销页承载 |
| 外部素材依赖 | 3/10 | 视觉由真实数据和程序化图形生成，不依赖容易失效的图库素材 |
| 品牌连续性 | 7/10 | 保留 AI SkillHub 名称、Logo、核心导航和安全原则 |

最高风险：把获奖展示站的全屏动效直接塞进日常工具，导致慢、晕、难找功能。因此采用“一套稳定操作骨架 + 一个数据驱动的动态视觉层”，而不是每个区域都做 WebGL 特效。

## 2. 现状诊断

保留：

- 当前 React/Tauri/Rust/SQLite 数据契约和所有真实操作入口。
- 现有四套 2.x 主题作为 Classic 分组，用户可随时切回。
- 全局搜索、同步状态、语言、评分、来源编辑、诊断和回滚能力。
- 已有的轻量 Canvas、`prefers-reduced-motion` 支持和语义状态色基础。

改善：

- 左侧宽导航 + 顶部工具条 + 多层卡片形成的通用 SaaS 感。
- 页面中几乎所有内容都被装进圆角卡片，层级靠阴影而不是排版和空间建立。
- 深色主题以紫蓝渐变为主，容易落入“AI 产品默认配色”。
- 冲突选择器同时展开全部组和全部候选，数据越多页面越长。
- 粒子目前主要是装饰，尚未表达来源、Skill、路由或同步状态。

移除：

- 无意义的泛光、重复状态胶囊、重复边框和每张卡都悬浮的效果。
- 把所有重名项都标成同一严重程度的“冲突”。
- 需要用户连续处理 132 组候选的工作流。

受保护契约：

- 不修改作者仓库，不静默删除或覆盖任何候选 Skill。
- Prompt 不能被当作 Skill 安装；只有包含 `SKILL.md` 的目录可调用。
- 未安装 Agent 时不创建假目录。
- 主题切换、本地评分和用户默认选择继续持久化。
- 所有同步、写入、回滚、诊断都有明确状态和审计记录。

## 3. 外部参考与转译

### FIELD.IO × IBM：Under The Surface

参考：<https://field.io/work/ibm-under-the-surface>

可借鉴：用真实数据构成空间图景，用户的 hover、grab、rotate 都对应数据探索，不是装饰。

转译：粒子分别代表来源、Skill 和路由；聚合距离表达父子关系；同步时粒子沿真实路由移动；冲突项以分叉轨迹表达。视觉层可关闭，核心操作不依赖粒子。

### FIELD.IO × IBM：Music Discovery Interface

参考：<https://field.io/work/ibm-x-grammy-museum-music-discovery-interface>

可借鉴：知识图谱不是背景，而是“发现入口”；连接在交互发生时出现。

转译：Dashboard 的 Skill Universe 只在搜索、筛选或选中来源时显露相关连接，避免长期满屏连线。

### Active Theory

参考：<https://activetheory.net/> 与 <https://www.webbyawards.com/crafted-with-code/active-theory/>

可借鉴：一次完整、编排明确的沉浸式场景，以及有物理感的过渡。

转译：只设置一个主舞台——Dashboard/Library 顶部的动态 Skill Atlas；列表、表格、设置和诊断继续保持高效稳定。不会复制 Active Theory 的品牌、场景或代码。

### Awwwards Interaction Design / WebGL

参考：<https://www.awwwards.com/websites/interaction-design/> 与 <https://www.awwwards.com/awwwards/collections/webgl/>

可借鉴：非传统导航、空间转场和指针反馈。

转译：用短时“坐标重排”表达页面切换和筛选结果，不用长滚动叙事，不隐藏常用按钮。

### Webby Best Data Visualization

参考：<https://winners.webbyawards.com/winners/websites-and-mobile-sites/features-design/best-data-visualization>

可借鉴：复杂数据首先要可理解，再追求视觉冲击。

转译：所有图形必须有文本摘要、筛选器、数字证据和键盘等价入口。

### 动效可访问性

参考：<https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion>

转译：遵守系统的 `prefers-reduced-motion`；另外提供“完整 / 平衡 / 静态”三级动效设置。静态模式保留所有信息和操作。

## 4. 新视觉概念：Kinetic Atlas / 动态图谱

一句话：**像一台来自研究实验室的精密仪器，而不是一张来自 AI 模板库的控制面板。**

视觉语言：编辑式排版、仪器刻度、可变网格、程序化点阵、硬边界、极少圆角。稳定导航是骨架，动态数据是皮肤。

### 色彩

新主题不使用紫粉渐变：

| 语义 | 暗色候选 | 亮色候选 | 用途 |
|---|---|---|---|
| 基底 | `#090B0A` | `#EEECE4` | 主背景 |
| 前景 | `#F2F0E8` | `#121512` | 正文与高对比结构 |
| Skill | `#C7FF45` | `#537A00` | Skill 节点、可调用状态 |
| Prompt | `#FF8A2A` | `#B94B00` | Prompt 与资料型来源 |
| Local | `#4C73FF` | `#2452D6` | 本地独立项 |
| Router | `#32D5C7` | `#007C74` | 父 Skill、别名和路由 |
| Danger | `#FF4D5E` | `#C52236` | 阻断和真实错误 |

颜色不是唯一状态信号；图标、标签文字、线型和位置同时表达类型。

### 排版

- 标题：窄体/扩展 grotesk 风格，减少“圆润 AI 字体”的软感。
- 正文：优先使用系统中英文字体，保证中文、英文、韩文一致可读。
- 路径、命令、评分和版本：等宽字体，形成“研究仪器读数”。
- 一级标题超大但只出现一次；日常列表保持紧凑。

### 形状与空间

- 主布局采用 72px 导航轨 + 可伸缩工作区 + 按需右侧 Inspector。
- 大部分内容使用分隔线、留白和网格，不再每项一张圆角卡。
- 只有浮层、可拖拽对象和关键确认区使用实体表面。
- 圆角以 0/4/10px 三档为主，不使用到处 20–28px 的软卡片。

### 动效语法

- 导航：当前页面像观测坐标一样滑动到新位置，180–260ms。
- 搜索：无关节点退场，匹配节点聚合，结果列表与 Atlas 同步高亮。
- 同步：来源节点向目标 Agent 发送脉冲，成功/失败轨迹可追溯。
- 冲突：同名候选以分叉线出现，选择默认后主线变实，别名支线仍保留。
- 页面不持续漂浮；空闲粒子速度很低，窗口失焦或不可见时暂停 RAF。
- 不加入自动播放音效；若未来有声音，只能显式打开。

性能预算：2D Canvas 优先；首版不引入 Three.js。DPR 上限 2，动态节点数量按窗口和设备降级，非活动页面暂停，目标普通 Windows 笔记本保持流畅。

## 5. 全新布局

### 全局骨架

1. 左侧 72px Atlas Rail：Logo、主要页面图标、当前位置、底部设置/安全入口。
2. 顶部 Command Deck：全局搜索、`/Skill` 命令提示、同步、语言、主题、运行状态。
3. 中央 Stage：每个页面拥有不同信息布局，但共享 12 列网格。
4. 右侧 Inspector：只有选择来源、Skill、冲突或 Agent 时出现；Esc 关闭。
5. 底部 Event Tape：短暂显示同步、评分、路由生成和诊断事件，可展开审计详情。

### Dashboard

- 首屏不是统计卡拼盘，而是可交互 Skill Atlas。
- 顶部用一行显示最重要的四个运行读数；详情通过 hover/focus 展开。
- Atlas 下方是“最近使用 / 高评分科研 Skill / 需要处理”三个紧凑流。
- 粒子代表真实数据；没有数据时显示清晰的导入引导，不生成假星空。

### Skill Library

- 左栏：来源与类型筛选，可折叠。
- 中央：高密度 Skill 表/网格切换，支持评分、健康、类型、来源和调用名排序。
- 右侧 Inspector：详情、评分、标签、调用命令、父子关系和来源证明。
- 父 Skill 与子 Skill 使用不同图形语法；Prompt、本地和其他类型保持独立语义色。

### Settings / Diagnostics

- 采用“参数表 + 证据抽屉”，减少卡片堆叠。
- 主题区明确分为“3.x Kinetic Atlas”和“2.x Classic”；切换即时生效，Classic 样式代码不被覆盖。

## 6. 冲突选择器重构为 Routing Observatory / 路由观测站

### 真实数据结论

- 当前索引：656 个 Skill，其中 20 个为 router hub。
- 同名冲突：132 组、268 个候选。
- 逐字/换行归一后完全相同：0 组。
- 基于非空正文行 Jaccard 相似度，89 组至少有一对相似度 ≥ 0.85。
- 28 组所有候选相似度都低于 0.70，属于真正的同名不同实现。
- 现有代码已经为每个候选生成稳定别名，例如 `/nature-paper-skills-figure-planner`，选择默认后再生成 `/figure-planner`；因此候选不会因为默认项而消失。

### 新分类

| 分类 | 判断 | 默认行为 |
|---|---|---|
| 等价镜像 | 去除易变元数据后语义指纹一致，依赖/脚本清单一致 | 自动选择规范来源，折叠展示，所有来源别名仍可调用 |
| 近似分叉 | 内容相似度高，但元数据、依赖或正文存在差异 | 自动推荐并解释，不宣称完全等价 |
| 独立实现 | 仅名称相同，正文相似度低 | 保留全部，自动推荐默认，突出能力差异 |
| 阻断项 | 文件缺失、别名无法生成或路由写入失败 | 不自动通过，进入“需要处理” |

### 自动默认评分

按以下顺序产生可解释推荐，绝不删除候选：

1. 用户明确保存的默认项。
2. 用户个人评分更高的候选。
3. 已启用、健康、文件和依赖清单完整的候选。
4. 非生成项优先于生成/打包镜像；直接来源优先于仓库内重复 vendor 副本。
5. 来源最近成功同步时间和版本信息。
6. 稳定的来源名 + 路径排序作为最终兜底，保证跨重启结果不漂移。

推荐需要记录 `reason_codes`、分数和时间。只有“等价镜像 + 高置信度”可静默自动路由；近似分叉和独立实现只自动给出可用默认，不隐藏提醒，用户可一键覆盖。

### 每个父子 Skill 都能调用

- 父入口：`/<source-or-collection>`，继续列出其全部子 Skill。
- 规范入口：`/<child>`，指向保存或推荐的默认候选。
- 来源入口：`/<source>-<child>`，每个候选始终生成并显示。
- UI 直接显示并可复制真实调用名，不创造与磁盘不一致的虚拟命令。
- 重新同步时先在临时目录生成路由清单，校验无碰撞后原子替换；失败保留上一次可用路由并写审计。

### 前端交互

- Skill Library 只显示一条紧凑摘要：“132 组 · 89 组可自动归纳 · 28 组需关注 · 0 阻断”。
- 点击进入固定高度观测站，不在页面内无限展开。
- 左侧是可搜索、可筛选、虚拟滚动的冲突队列，默认只显示“需要关注”。
- 中央使用行式比较表：来源、个人评分、健康、相似度、依赖、真实调用名、推荐原因。
- 右侧 Inspector 展示差异摘要和路由预览。
- 支持“接受全部安全建议”，但不提供“忽略且隐藏全部”的危险捷径。
- 已解决项进入折叠历史，可随时重选；默认变更生成明确 toast 和审计记录。

## 8. 验收标准

功能：

- 132 组冲突全部可分类；每个候选都有可复制、可验证的真实调用入口。
- 父入口、默认子入口、来源别名在同步后均能从目标 Agent 目录解析。
- 手动默认、自动推荐、个人评分和重新同步后状态可持久化。
- Classic 与 Atlas 主题均可运行，不改变作者仓库。

体验：

- 冲突面板高度不随冲突组数量增长；100+ 组仍可快速搜索和键盘操作。
- 1280×720、1920×1080、HiDPI 和窄窗口无横向溢出。
- 完整、平衡、静态三种动效均可完成全部任务。
- 类型不只靠颜色区分；键盘焦点、屏幕阅读标签和对比度通过检查。

性能：

- Canvas 不可见时停止绘制；窗口失焦降帧。
- 不因 Atlas 主题引入大体积 WebGL 依赖。
- 生产构建、Rust 测试、Clippy、依赖审计、浏览器控制台、桌面窗口 QA 和干净电脑模拟全部通过后才形成 3.x 正式包。

## 10. Checkpoint 2 视觉修订：Living Atlas（2026-07-23）

首版 v0 被否决，原因不是“暗色不够漂亮”，而是错误地把 FIELD.IO / Active Theory 的空间体验翻译成了传统控制台：全局网格、硬直角边框、酸性绿和大量细框抢走了粒子主体，首页仍然是卡片式 Dashboard。

修订后的设计纪律：

1. **一个最大视觉时刻**：只有 Dashboard 首屏使用全屏数据宇宙；内页不重复制造多个视觉奇观。
2. **数据塑形**：粒子数量由 Skill 数量、聚类数量由来源数量驱动；不是与产品无关的循环背景视频。
3. **空间可交互**：指针改变球体视角、景深和局部场扰动；轨迹、连线、星尘和能量核共同表达来源、关系和活跃路径。
4. **文字退到舞台边缘**：标题和操作位于左侧，能力球占据右侧；实时读数和预览提示变成小型浮层，不再横切画面。
5. **内页回归工具性**：Skill Library 与 Routing Observatory 保留已认可的信息架构，去除全局网格和硬边框，改用低对比玻璃材质、柔和圆角与稀疏背景粒子。
6. **配色重置**：深空底、光谱白、冷青与雾蓝为主，暖金只表达活动信号；移除酸性绿和“黑曜”命名。主题显示名改为“活体图谱 · 深空 / 雾光”。
7. **性能与可访问性**：继续采用零新增依赖的 2D Canvas 透视投影；DPR 受限、页面隐藏时暂停、内页降低密度，并遵守 `prefers-reduced-motion`。

本轮仍是 Checkpoint 2 的修订原型。它只调整前端视觉与动效，不提前启用语义指纹、自动路由写入、正式版本号、打包或推送。
